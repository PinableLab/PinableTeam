# 飞书群通知（第一阶段）

Bot 管理可选择企业微信或飞书。旧配置没有 channel 字段时仍使用企业微信，不需要数据迁移。已有 Bot 不允许更换渠道；需要新建，避免凭据或接收会话串用。

## 扫码添加（推荐）

1. 登录 PinableTeam，在有通知配置权限的项目中打开通道管理，新建“飞书（群通知）”Bot，填写用于在项目中识别它的名称。
2. 生成二维码，用飞书移动端扫码并完成应用创建授权。扫码后回到 PinableTeam，点击“保存机器人”。这一步只保存一个未启用的通知 Bot，并不自动发消息或开启对话。
3. 如飞书侧要求发布、补充权限或审批，请先按飞书提示完成。把机器人加入接收群，在 PinableTeam 刷新群列表并保存目标。
4. 确认接收群后手动启用 Bot，再用现有测试入口验证，并在 SOP 或定时任务的通知设置中选择它。

二维码只在短时间内有效。关闭、取消或重启服务后，未保存的扫码过程需要重新发起。取消 PinableTeam 的表单不会删除飞书端已创建的应用。扫码创建只支持飞书国内版。

## 手动配置已有应用

通过“手动填写 App ID / Secret”添加已有应用。应用需启用机器人、发布并开通读取所在群和发送消息权限；加入接收群后，按上面的步骤选择群、手动启用和测试。消息经飞书 REST API 发出，不需要开放公网回调端口。

凭据使用现有服务端凭据存储（不是应用级加密）；浏览器不会收到已保存的 Secret。默认只连接 open.feishu.cn，不支持自定义 API 域名、国际版 Lark 或群自定义 webhook。当前群列表不包含私人聊天。发送的是纯文本，不将任意任务输出解释为交互卡片。

## 明确不支持

本阶段不接收飞书消息、不执行飞书聊天任务、不处理审批按钮。飞书 Bot 的“启用对话”在 UI 禁用，服务端也拒绝启用。原企业微信互动协议保持不变，飞书凭据不会进入企业微信长连接。
